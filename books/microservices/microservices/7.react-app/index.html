    Chapter-7: Build the Storefront with React

    Sample code

    The complete, tested code for this chapter is in samples/microservices/storefront. Use it to compare against your own work.

    Introduction

    In this lab, we will build the Storefront, the website our customers use to browse the products and fill their shopping cart. Where the Admin site builds every page on the server, the Storefront is a single-page application (SPA) written with React: the browser downloads the app once, and JavaScript then draws and updates the page without reloading it.

    We will create the project with Vite, write a small store page, and package it with a multi-stage Dockerfile into an nginx image that serves the finished site.

    Technical Scenario

    As a Frontend (FE) developer, you have been assigned the task of building the Storefront of our online store. Customers use it to:

    • see the list of products with their prices,
    • add products to a cart and change the quantities,
    • place the order.

    The Storefront owns no data. In the finished store, it reads the products from the Product API and sends orders to the Order API, both through the gateway. Because the gateway serves the Storefront and the APIs on one address, the app calls relative /api/... URLs and needs no runtime configuration, such as an API address per environment (Chapter-15). In this chapter it runs on its own: the product list comes from a static JSON file served with the site, the cart lives in the page, and the Place order button stays disabled. Chapter-14 replaces the static file with the live products from the Product API and connects the button to the Order API.

    Objective

    In this exercise, our objective is to accomplish and learn the following tasks:

    • Step-1: Install Node.js and NPM
    • Step-2: Create a new React application
    • Step-3: Build the store page
    • Step-4: Add the nginx configuration and Dockerfile
    • Step-5: Docker build and run locally
    • Step-6: Push docker container to ACR (optional)

    Prerequisites

    • The microservices repository from Chapter-4, cloned locally
    • Node.js 24 (LTS) and npm
    • Docker Desktop
    • Visual Studio Code or another code editor
    • For the optional step only: an Azure Container Registry (ACR)

    Step-1: Install Node.js and NPM

    To build a React app, you need Node.js and npm (Node Package Manager), which comes with it. If you followed Chapter-5, you already have them.

    Otherwise, download the LTS installer from https://nodejs.org/en/download, or install it from the command line:

    • Windows with Chocolatey (run as administrator):

      choco install nodejs-lts

    • macOS with Homebrew:

      brew install node@24

      Follow the instructions Homebrew prints to add it to your PATH.

    Verify the installation:

    node --version
# v24.9.0

# 11.6.0

    Step-3: Build the store page

    The app

    Replace src/App.jsx with:

    src/App.jsx
    import { useEffect, useState } from 'react'

const formatPrice = (price) => price.toFixed(2)

function ProductList({ products, onAdd }) {
  return (
    <ul className="products">
      {products.map((product) => (
        <li key={product.id} className="product">
          <h3>{product.name}</h3>
          <p>{product.description}</p>
          <div className="product-footer">
            <span className="price">{formatPrice(product.price)}</span>
            <button type="button" onClick={() => onAdd(product.id)}>
              Add to cart
            </button>
          </div>
        </li>
      ))}
    </ul>
  )
}

function Cart({ lines, onAdd, onRemove }) {
  const total = lines.reduce((sum, line) => sum + line.price * line.quantity, 0)

  return (
    <aside className="cart">
      <h2>Your cart</h2>
      {lines.length === 0 ? (
        <p>Your cart is empty.</p>
      ) : (
        <ul>
          {lines.map((line) => (
            <li key={line.id}>
              <span>{line.name}</span>
              <span className="quantity">
                <button type="button" onClick={() => onRemove(line.id)} aria-label={`Remove one ${line.name}`}>
                  -
                </button>
                {line.quantity}
                <button type="button" onClick={() => onAdd(line.id)} aria-label={`Add one ${line.name}`}>
                  +
                </button>
              </span>
              <span>{formatPrice(line.price * line.quantity)}</span>
            </li>
          ))}
        </ul>
      )}
      <p className="total">Total: {formatPrice(total)}</p>
      {/* A span carries the tooltip, because disabled buttons don't show one in every browser */}
      <span title="Ordering is not available yet">
        <button type="button" disabled>
          Place order
        </button>
      </span>
    </aside>
  )
}

function App() {
  const [products, setProducts] = useState([])
  const [error, setError] = useState(null)
  // The cart maps a product id to a quantity, for example { 1: 2 }
  const [cart, setCart] = useState({})

  useEffect(() => {
    let ignore = false
    // Temporary: a static file served with the site.
    // A later chapter loads the products from the Product API instead.
    fetch('/products.json')
      .then((response) => {
        if (!response.ok) throw new Error(`HTTP ${response.status}`)
        return response.json()
      })
      .then((data) => {
        if (!ignore) setProducts(data)
      })
      .catch((err) => {
        if (!ignore) setError(err.message)
      })
    return () => {
      ignore = true
    }
  }, [])

  function addToCart(id) {
    setCart((current) => ({ ...current, [id]: (current[id] ?? 0) + 1 }))
  }

  function removeFromCart(id) {
    setCart((current) => {
      const { [id]: quantity, ...rest } = current
      return quantity > 1 ? { ...current, [id]: quantity - 1 } : rest
    })
  }

  const cartLines = products
    .filter((product) => cart[product.id])
    .map((product) => ({ ...product, quantity: cart[product.id] }))

  return (
    <>
      <header>
        <h1>Store</h1>
      </header>
      <main>
        <section>
          <h2>Products</h2>
          {error && <p role="alert">Could not load the products: {error}</p>}
          <ProductList products={products} onAdd={addToCart} />
        </section>
        <Cart lines={cartLines} onAdd={addToCart} onRemove={removeFromCart} />
      </main>
    </>
  )
}

export default App

    The page is made of three React components:

    • ProductList shows a card for each product with an Add to cart button.
    • Cart shows the cart lines, buttons to change the quantities, the total, and the Place order button, which is disabled for now.
    • App holds the state: the products, a possible error, and the cart. When the state changes, React redraws the parts of the page that depend on it.

    useEffect with an empty list [] runs once, after the page first appears, and fetches the products. The ignore flag is the React way to ignore a response that arrives after the component is gone. The cart is stored as product ids and quantities only; cartLines combines it with the product list every time the page is drawn, so the cart can never show a stale name or price.

    Replace src/index.css with the plain CSS from the sample. It lays the products out in a grid with the cart beside them, stacks them on narrow screens, and follows the light or dark mode of your operating system. src/main.jsx from the template already imports it, so it needs no changes.

    Step-4: Add the nginx configuration and Dockerfile

    The development server is great while coding, but it is not meant to serve real users. For production, npm run build compiles the app into a few static files in the dist folder, and any web server can serve them. We use nginx, a small and very fast web server.

    The nginx configuration

    Create nginx.conf in the storefront folder:

    nginx.conf
    server {
    # nginx-unprivileged runs as a normal user, which may not open ports below 1024
    listen 8080;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    location / {
        # Serve the file if it exists, otherwise index.html, so the React app
        # handles every page address (single-page application fallback)
        try_files $uri $uri/ /index.html;
    }
}
    • root is the folder nginx serves files from; the Dockerfile copies our built site there.
    • try_files is the SPA fallback. A single-page application has one real HTML file, but as it grows it shows different pages at addresses like /orders/123. No such file exists on the server, so without this line nginx would answer 404 when a user reloads that page or opens a bookmark. try_files first looks for a matching file (such as /products.json or a JavaScript file), and otherwise returns index.html, so the React app starts and shows the right page.
    • listen 8080 instead of the usual port 80: see the next section.

    The Dockerfile

    Create a Dockerfile:

    Dockerfile
    # Build stage: compile the static site with Vite
FROM node:24-alpine AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Serve stage: nginx running as a non-root user on port 8080
FROM nginxinc/nginx-unprivileged:alpine AS final
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 8080
USER nginx

    This is a multi-stage Dockerfile:

    • The build stage uses Node.js to install the dependencies (npm ci, including the development tools such as Vite) and to build the static files (npm run build) into /app/dist.
    • The final stage starts from a clean nginx image and copies in only two things: our nginx.conf, which replaces nginx's default site, and the built files from the build stage. The final image contains no Node.js, no node_modules and no source code, so it is small, and no development server runs in the container.

    Why nginxinc/nginx-unprivileged instead of the official nginx image? The official image starts as root so that it can open port 80; on Linux only root may open ports below 1024. The unprivileged variant, published by the nginx team, runs as the nginx user from the start and therefore listens on port 8080. Running as a normal user means a flaw in the web server doesn't hand an attacker root rights in the container. USER nginx makes that choice visible in our own Dockerfile.

    Finally, add a .dockerignore file so that your local node_modules and dist folders are not sent to Docker. The build stage creates both itself:

    .dockerignore
    node_modules
dist

    Step-6: Push docker container to ACR

    This step is optional. It pushes the image to Azure Container Registry (ACR), the same way as in Chapter-4; replace the example registry name acr1dev with your own.

    1. Log in to Azure and to your registry:

      # Azure login
az login

# set the azure subscription
az account set -s "<subscription-name>"

# Log in to the container registry
az acr login --name acr1dev

    2. Tag the image with the full name of your registry, and push it:

      docker tag sample/storefront:1.0 acr1dev.azurecr.io/sample/storefront:1.0
docker push acr1dev.azurecr.io/sample/storefront:1.0

      Output (example; layer ids and digest differ on your machine):

      The push refers to repository [acr1dev.azurecr.io/sample/storefront]
<layer-id>: Pushed
...
1.0: digest: sha256:<digest> size: <size>

    3. Verify the image and its tag in the registry:

      az acr repository show-tags --name acr1dev --repository sample/storefront --output table

      The output lists the tag 1.0.

    Conclusion

    In this chapter, we built the Storefront, the React single-page application where customers browse the products and fill their cart. We used Vite to create and build the app, and a multi-stage Dockerfile to serve the finished files from a small nginx image that runs as a non-root user on port 8080, with a fallback that lets the React app handle every page address.

    We now have all four parts of the store that customers and staff use: the Product API, the Order API, the Admin site and the Storefront. Each one runs on its own, with its own temporary data. In the next chapters, we give the services real databases and then connect everything into one system.
